# Mac 风扇控制协议兼容依据

核实日期：2026-10-19。此文区分源码协议依据、模拟验证与真机验证；不把上游支持范围视为 Ermi 已完成全部机型实测。

## 一手来源

[Stats SMC/smc.swift，固定 commit 573145558badb690728e39f3b2dcdb490e2ea731](https://github.com/exelban/stats/blob/573145558badb690728e39f3b2dcdb490e2ea731/SMC/smc.swift)

- `fanModeKey`（368–377）：Apple Silicon 探测小写 `F0md`，否则大写 `F0Md`；Intel 使用大写。
- `setFanMode`（380–467）：编号只接受 0...9。Apple Silicon 恢复先将模式置为自动，再把目标清零。Intel 修改存在的 per-fan `Md`，同时对 `FS! ` 两字节大端掩码设置/清除该风扇位，保留其余位。
- `setFanSpeed`（470 起）：按 `F?Mx` 限制范围，目标键为 `F?Tg`；目标编码来自硬件 metadata。
- `unlockFanControl`（559 起）：先直接请求手动模式，失败后才尝试存在的 `Ftst`，等待系统控制器释放；不是所有 Apple Silicon 系统均有 `Ftst`。
- `resetFanControl`（607 起）：按 `FNum` 枚举风扇，不假设必须两只。

## Ermi 实现边界

- 不再以机型型号白名单阻止 M2/M3/M4 等机器；CPU 品牌仅识别 Intel 或 Apple M 协议族，实际能力由读取键、类型、字节长度、范围和模式验证。未知架构、未知类型、驱动错误均拒绝写入。
- `FNum` 必须是 `ui8 ` 且在 0...10；0 表示无风扇，返回空列表。10 以上不能静默截断。每只风扇独立验证最小、最大和目标 RPM，以及适用模式寄存器。
- Intel 必须存在有效 `FS! ` (`ui16`, 2 字节)；`F?Md` 可缺失。任一寄存器报告手动都视为其他控制器占用；确认写入和恢复时要求所有存在的模式寄存器一致。恢复不把 Intel 目标清零。
- Apple Silicon `F?md/Md` 必须有效；只有 missingKey 可以触发大小写回退。保留直接模式、可选 `Ftst`、确认后目标写入顺序。
- 日志保存每只已接管风扇的协议，恢复时核对硬件当前能力；旧日志没有协议字段时只允许原 per-fan 协议迁移。空日志恢复不访问 SMC，避免未知硬件阻止 helper 接收诊断请求。
- 只对已接管风扇恢复。Intel 掩码每次读取最新值并只改自己的位；SMC 没有 compare-and-swap，无法保证与其他程序同时写同一掩码时的原子性，已有回读校验用于检测自身模式失败。

## 验证与限制

模拟测试覆盖单风扇 M4、4 风扇 Intel、无风扇、未知架构拒绝、格式异常拒绝、其他风扇位保留、双寄存器占用、模式/目标延迟或未生效、恢复和取消边界。没有在 M4 或 Intel 真机执行硬件写入；仍需各机型实测固件是否接受操作。日志权限校验保留 root 独占要求，不能为普通用户测试降低生产权限规则。
