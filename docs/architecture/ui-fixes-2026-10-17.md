### 去除等待文案后的服务忙冲突

用户继续遇到「正在处理上一条控制请求」。来源是 ServiceRuntime.apply 的 operation guard：周期 tick 同样占用 operation，因此客户端已串行也可能被定时采样拒绝。现仅对 tick 使用 continuation 等待，结束后复查连接存活、owner、退出和 recoveryRevision，再应用。恢复中不排队；等待中发生恢复则废弃旧选择，避免重新接管。真实并发 apply 的拒绝仍保留，不能把未执行伪装成成功。

ServiceRuntimeTests 3项通过，覆盖 tick 等待后应用、等待期间断连禁止写入、恢复与断连合并的原有行为。第一次测试发现恢复中 apply 等待 tick 会造成测试死锁，已将 recovery 检查提前，复测通过。构建日志 `/tmp/ermi-tick-wait-build.log`。本轮修改 Helper，需要更新安装后才能验证真机效果。
