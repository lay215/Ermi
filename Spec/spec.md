# 自定义温控传感器

## 范围

在菜单栏弹窗的自动调节行和风扇详情页直接选择内置方案的温度来源，无需新建方案。保留 CPU、GPU、CPU / GPU 最高三个既有来源，并可直接选择具体 SMC 温度传感器；日常均衡和积极散热共享这一默认选择，未设置时沿用 CPU / GPU 最高。自定义方案仍通过原编辑器保存自己的来源。按用户最新要求，弹窗主温度与默认选择同步：CPU/GPU 使用既有推荐映射，最高值要求两者都有效，具体键精确读取且缺失时显示不可用。菜单栏摘要与概览的 CPU/GPU 指标保持原语义，不修复或替换芯片温度映射。

## 行为与边界

- 弹窗温度来源标签独占大温度读数下方一行，不放在 °C 单位旁。右侧统一显示同一轮采样的 CPU / GPU 温度，使用 °C；CPU 使用率继续在系统概览展示，不在该温度对照行混入百分比。选择 CPU / GPU 时，大温度与右侧对应项目使用相同映射及四舍五入格式，缺失显示不可用。
- 候选来自有界、只读 SMC 键发现及当前采样，展示稳定键名和实时温度。未经验证的用途不标成 CPU/GPU，提示用户观察变化再选择。
- 候选详情仅在编辑器、选择入口或显示具体传感器温度的弹窗可见时随普通采样更新；关闭窗口或离开入口后停止额外详情采样。已保存但暂不可读的键保留选中，不自动换源。
- 运行内置方案时直接选源走原 apply 校验与回读，确认成功后才记住新选择；失败保留原选择。系统、固定转速或自定义方案运行时，选择仅保存为内置方案默认值，不切换模式或改写自定义规则。切换两个内置方案及重新启动时保留选择；仍以最后成功配置恢复实际控制。
- 保存只持久化预设。点击“使用”或已有的启动恢复流程才提交控制请求。
- 具体来源必须是四字节 ASCII 字母数字键，首字母 T，且读取类型为已支持的温度类型。helper 自行重新读取该键，App 不向 helper 提供用于控制的温度数值。
- 读数缺失、非有限、超出有效范围或样本过期时拒绝控制；已接管时沿用既有恢复机制，恢复未确认时显示待恢复状态。不得回退 CPU/GPU 或其他键。
- 既有预设 JSON 保持可读，原来源不允许携带自定义键。新来源有独立枚举值，旧 helper 不会忽略新字段后误用原来源。
- helper 在 inspect 回包声明支持自定义来源；App 未收到明确支持时阻止应用并提示更新授权。构建 App 不等于更新系统已安装 helper。
- 新预设包含旧程序不认识的来源，降级后的旧程序可能无法读取含此来源的预设文件；不自动改写为另一来源。

## 验收

- 具体源与 CPU/GPU 读数不同时，以所选键计算转速。
- 缺失/无效/过期读数触发恢复，不静默换源；非法键在读写前拒绝。
- 保存往返、旧 JSON 兼容、旧来源保留、未知来源被旧解码器拒绝。
- 候选发现有界并缓存，实时值不缓存成有效旧读数；普通监控和 helper 默认不扫描所有候选。
- 新旧服务支持字段兼容；旧服务不能收到自定义来源的 apply，保存不会发送硬件请求。
- 编译、自动化回归和代码审查完成；模拟设备测试不等于真实机型调速验收。
